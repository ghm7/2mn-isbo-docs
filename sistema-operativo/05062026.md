# Permisos y propiedades

## Sistemas operativos

Es un sistema GNU/Linux, todos los recursos están asociados a un propietario.
Esta idea es la base de todo modelo de seguridad: el sistema operativo necesita
saber quien esta haciendo algo para decidir si tiene permiso o no de hacerlo.

## El modelo en tres categorías

### Propietario (user)

El usuario que creo el archivo o al que se le asignó.

### Grupo (group)

Los usuarios que pertenecen al grupo asociado al archivo.

### Otros (others)

Cualquier otro usuario del sistema que no sea ni propietario, ni miembro del
grupo de propietario.

## Los tres tipos de permisos

El sistema evalúa estas tres categorías en orden:

Primero verifica si el que quiere acceder es el propietario, si lo es, aplica
los permisos del propietario y se detiene. Si no, verifica si pertenece al
grupo, y si tampoco, aplica los permisos de otros.

### Lectura (r)

Permite ver el contenido de un archivo o listar el contenido de un directorio.

### Escritura (w)

Permite modificar un archivo, o crear y eliminar archivos dentro de un
directorio.

### Ejecución (x)

Permite ejecutar un archivo como programa o ingresar a un directorio y acceder a
su contenido.

## 8 Estados de los permisos

- 0 - Ausencia
- 4 - Lectura
- 2 - Escritura
- 1 - Ejecución

> [!NOTE]
>
> Quien aplica permisos sobre un archivo?
>
> El propietario y/o el root

## Porqué importa esto?

Este modelo garantiza que, incluso si varios estudiantes comparten el mismo
equipo, cada uno solo puede acceder a sus propios archivos. A su vez, el
docente/administrador puede definir que recursos son compartidos y en que
medida. Es una forma elegante de organizar el acceso sin necesidad de
contraseñas separadas para cada archivo.

> [!NOTE]
>
> Existe un indicador mas en los permisos, que te dice que tipo de elemento es
> \- - archivo
>
> d - directorio
>
> l - link

# Terminal

Una 'terminal' no es otra cosa que un entorno de entrada y salida de texto por
eso decimos que es el primer elemento de contacto entre la maquina y el usuario
humano.

Cuando decimos 'consola' hablamos de un sub tipo de terminal, por lo tanto nos
induce a pensar en un dispositivo físico como un teletypes y en ella coexistía
pantalla y teclado.

> [!NOTE]
>
> Una computadora procesa datos, almacena, envía
>
> Un aparato electrónico procesa datos
>
> Un aparato eléctrico solo funciona con energía pero no procesa datos ni
> almacena
>
> Una consola procesa datos, envía pero no almacena

Pasamos a términos más complejos como: emulador de terminal donde tenemos
ejemplos como aplicaciones llamadas konsole, gnome-terminal, xterm.

Por su parte una línea de comandos es nada más que la parte derecha del prompt y
tiene por lo general tiene un aspecto intermitente para indicar que el terminal
está listo para recibir comandos del usuario.

Un intérprete de comandos es quién interpreta esos comandos que colocamos en
pantalla. El rol del intérprete de comandos es traducir esa orden y enviarla al
kernel. El intérprete de comandos tiene reglas definidas con sintaxis y
estructura, es decir, lo que se puede hacer y aquello que no. Es el intérprete
quien traduce el comando a una llamada del sistema que el kernel puede
comprender.

- bash
- dush
- zsh
