# Formas de normalización

## Segunda forma normal

- Viajes (<u>Matrícula</u>, <u>CI</u>, <u>fecha</u>, kilómetros, nombre, modelo)

### Dependencias funcionales

- CI ->> nombre
- Matrícula -->> modelo
- Matrícula, ci, fecha -->> kilómetro

Para formar una tabla en primer a forma normal NO PODEMOS tener atributos multi
valor (\*) ni a { b, c, d }

- modelo tiene una dependencia funcional parcial en Matricula porque también CI
  depende de funcionalmente
- kilómetros tiene una dependencia funcional total de Matricula, CI y fecha

Entonces para poder **normalizar** la tabla eliminamos nombre y modelo de la
primer tabla y la movemos a la siguiente

- Viajes (<u>Matricula</u>, <u>CI</u>, <u>fecha</u>, kilómetros, nombre, modelo)
- Chofer (<u>CI</u>, nombre)
- Vehículo (<u>Matricula</u>, modelo)

## Tercerca forma normal

En este ejemplo vemos como nombre y apellido son **dependencias funcionales
transitivas**

- Alquileres (<u>NCabaña</u>, <u>fecha</u>, cantDias, CI, nombre, apellido)

### Dependencias funcionales

- NCabaña, fecha ->> cantDias, CI, nombre, apellido
- CI ->> nombre, apellido (dependencia funcional transitiva)

Entonces para normalizar esto eliminamos nombre y apellido de la primer tabla

- Alquileres (<u>NCabaña</u>, <u>fecha</u>, cantDias, CI)
- Inquilinos (<u>CI</u>, nombre, apellido)

## Primera forma normal

- Tablas con clave valor
- Sin atributos multivalor `*` o derivados `{ }`

### 1 FN

- Estudiante (<u>CI</u>, nombre, apellido)
- EsTutor (<u>CI</u>, <u>CiT</u>, nombreT, apeT, vinculo)
- actua (<u>idMateria</u>, <u>nombreGrupo</u>, <u>CI</u>, nota, CIDoc, nomDoc,
  apeDoc)

## Segunda forma normal

- Verificar solamente tablas con claves compuestas

### 2 FN

- EsTutor (<u>CI</u>, <u>CIT</u>, vinculo)
